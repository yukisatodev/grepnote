# コンセプト: grepnote

## 課題

エンジニアや学習者は、技術記事の要点・コードスニペット・学習メモを日々書き溜める。
だが書く場所はメモアプリ、ブックマーク、Notion、走り書きのテキストファイルと分散しがちで、
数か月後に「あの話、どこかにメモしたはずなのに見つからない」という状態になりやすい。

検索できないメモは、存在しないメモとほぼ同じ価値しか持たない。

## 誰のためのものか

- 日常的に技術メモを取る、自分自身を含むエンジニア・学習者
- メモの量が「タイトルを覚えていれば探せる」規模を超えた人

## なぜ「検索エンジンを自作する」のか

既存のメモアプリにも検索機能はある。しかしこの作品の目的はメモアプリを作ることではなく、
「検索とはどういう仕組みで成り立っているか」を自分の手で実装し、意思決定の過程を見せること。

- 単純な文字列一致(`includes()`)ではなく、転置インデックスを自作する
- 日本語・英語が混在するメモを、外部の形態素解析ライブラリに頼らず処理する
- 件数が増えても検索が破綻しない設計を、小さい規模のうちから考える

「メモを検索できるようにする」というシンプルな課題の裏にある、
データ構造・アルゴリズム・永続化設計の判断を見せるための題材として選んでいる。

## このポートフォリオで伝えたいこと

- 課題に対して、いきなりライブラリに頼らず仕組みを理解した上で選択している
- 小さい規模のツールでも、将来のスケールを見据えた層分離(UI / ロジック / データ)をしている
- 完璧を装わず、判断の限界や妥協点も明示している([04-tradeoffs.md](./04-tradeoffs.md)参照)
